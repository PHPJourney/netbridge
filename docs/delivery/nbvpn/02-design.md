# Design: 网桥 VPN — Store 落地页 + 四端客户端

> 对齐：`01-spec.md` / `03-contract.md` / Context Pack  
> 验收：`slices/S03-clients/acceptance.md`、`slices/S04-download-site/acceptance.md`  
> 设计源：仓库无既有 UI；以本文档为唯一设计交接（无 Figma 节点时前端按本文实现）  
> 日期：2026-08-14

## 设计目标（1–3 句）

1. Store 页让访客 **30 秒内**分清「下客户端 / 下服务端」，并用 ≤3 步走完自建主路径。  
2. 四端客户端信息架构一致：空列表 → 三形态添加 → 一键连接；无账号、无官方节点入口。  
3. 全链路强调「连接信息 = 密钥」的安全提示，但不打断傻瓜式主路径。

## 信息架构 / 导航

### Store（单页为主）

```text
网桥 VPN Store（落地页）
├── 顶栏：品牌「网桥 VPN」+ 锚点（使用步骤 | 客户端 | 服务端 | 责任说明）
├── Hero：品牌主导 + 一句话价值 + 双 CTA（下载客户端 / 部署服务端）
├── 三步指引（固定 3 步，不可扩成功能矩阵）
├── 客户端下载区（Win / macOS / Android / iOS）
├── 服务端下载区（Debian / Ubuntu / CentOS / RHEL + Rocky/Alma 说明）
├── 责任与去中心化说明（页脚上方）
└── 页脚：版本汇总入口、校验和说明链接（无登录、无节点列表）
```

**禁止导航项**：登录/注册、节点列表、套餐、一键连接官方。

### 客户端（四端同构）

```text
网桥 VPN App
├── 主页：服务器列表（空态 / 列表态）+ 全局连接状态条
├── 添加服务器（三入口：粘贴 URI | 导入文件 | 扫码）
├── 服务器详情/操作：连接·断开·改名·删除
├── 设置：Kill Switch、（可选）开机启动、关于/责任声明
└── （无）账号、商城、发现节点
```

桌面（Win/macOS）：主窗口 + 系统托盘/菜单栏快捷连接。  
移动（Android/iOS）：主列表 + 系统 VPN 权限引导页（首次连接时）。

## 关键流程（页或模态顺序）

### F-W 访客：Store 下载

```text
打开 Store
  → 读 Hero + 三步
  → A) 点「部署服务端」→ 滚到服务端区 → 选发行版 → 下载/复制安装命令
  → B) 点「下载客户端」→ 滚到客户端区 → 选平台下载
  →（并行）装服务器 → nbvpn show → 回客户端添加
```

### F-C1 新用户：空列表 → 添加 → 连接

```text
打开 App（空态）
  → 主 CTA「添加服务器」
  → 选择方式：URI | 文件 | 扫码
  → 解析成功 → 「确认添加」页（可改本地名称 + 密钥警告）
  → 回到列表 → 点「连接」
  →（移动）系统 VPN 授权
  → 状态：连接中 → 已连接
```

### F-C2 导入失败

```text
粘贴/扫码/文件
  → 校验失败
  → 错误页/横幅：可读原因 +「重新输入」；不写入列表
```

### F-C3 改名 / 删除 / 切换服务器

```text
列表项菜单 → 重命名（仅 localName）
删除 → 确认对话框 → 若正在连接先断开再删
连接另一台 → 先断当前 → 再连目标（同时仅一条）
```

### F-C4 断线与重连

```text
已连接 → 网络中断
  → 状态「重连中」或错误文案（可复制）
  → 网络恢复 → 自动重连成功 / 失败保留「重试」按钮
```

## 关键界面清单

### Store

| 界面 ID | 名称 | 状态（默认/空/错/加载） | 设计源 |
|---------|------|-------------------------|--------|
| W-01 | Store 落地页整页 | 默认：有版本与下载链接；加载：链接拉取中骨架；错：某平台链接失败显示「暂时不可用+校验说明仍可见」 | 本文档 |
| W-02 | 客户端下载卡片×4 | 默认：平台名+版本+SHA256+下载按钮；空：不出现「即将提供」（本次 must 齐套） | 本文档 |
| W-03 | 服务端下载/命令块×4 系 | 默认：发行版名+安装命令一键复制+包下载；附 Rocky/Alma 使用 CentOS/RHEL 入口说明 | 本文档 |
| W-04 | 三步指引条 | 默认固定文案（见文案节） | 本文档 |
| W-05 | 责任说明块 | 默认展示；无折叠隐藏关键责任句 | 本文档 |

### 客户端（逻辑界面，四端复用同一 ID）

| 界面 ID | 名称 | 状态 | 设计源 |
|---------|------|------|--------|
| C-01 | 服务器列表主页 | **空**：插画/简洁空态+「添加服务器」；**列表**：项含名称、状态点、连接按钮；**加载**：首次读本地存储 | 本文档 |
| C-02 | 添加方式选择 | 三按钮：粘贴 URI / 导入文件 / 扫码（桌面扫码=摄像头或「从图片识别」should） | 本文档 |
| C-03 | 粘贴 URI | 默认大输入框+粘贴；错：E_URI_* 文案；加载：校验中 | 本文档 |
| C-04 | 导入文件 | 系统文件选择器；错：文件无效；仅突出 `.nbvpn.json` | 本文档 |
| C-05 | 扫码 | 相机取景；错：无权限/无法识别；成功震动/提示后进 C-06 | 本文档 |
| C-06 | 确认添加 | 显示建议名（可编辑）、endpoint 摘要（非私钥）、密钥警告；主按钮「添加」 | 本文档 |
| C-07 | 连接中/已连接/失败 | 状态条颜色区分；失败可复制错误；已连接显示「断开」 | 本文档 |
| C-08 | 重命名 | 单行输入；保存/取消 | 本文档 |
| C-09 | 删除确认 | 说明将删除本地配置；若已连接注明将断开 | 本文档 |
| C-10 | VPN 系统权限引导 | 移动端首次；说明为何需要 VPN 权限；无账号话术 | 本文档 |
| C-11 | 设置 | Kill Switch 开关（默认开或首次引导开，与规格一致）；关于+责任链接；无登录项 | 本文档 |
| C-12 | 版本过高等待升级 | `v` 过高：阻断导入+「请升级客户端」 | 本文档 |

## 组件与复用

| 组件 | 用途 | 备注 |
|------|------|------|
| BrandMark | 「网桥 VPN」词标 | Store Hero 与 App 顶栏同源；品牌为第一视觉，不被副标题压过 |
| PrimaryButton / SecondaryButton | 主次操作 | 连接=主；断开=次或危险态 |
| PlatformDownloadCard | Store 客户端四卡 | 图标+版本+checksum+CTA |
| DistroInstallBlock | 服务端四系 | 命令块+复制按钮+可选包链 |
| StepStrip | 三步指引 | 仅 3 步，禁止加统计/促销条 |
| ServerListItem | 列表行 | 名称、状态点、主操作 |
| StatusBanner | 全局连接状态 | 未连接/连接中/已连接/重连中/错误 |
| SecretWarningCallout | 密钥警告 | C-06 与 Store 责任区可复用语气 |
| ErrorCopyable | 错误文本+复制 | CL 失败、导入失败共用 |
| EmptyState | C-01 空态 | 无假服务器、无「推荐节点」 |

**视觉方向（Store + App 统一，避免通用 AI 紫白风）**

- 意象：桥/链路/稳固节点；深青灰（`#0F1C24`）底 + 亮青（`#2EC4B6`）强调 + 暖中性文字，非紫渐变、非奶油衬线刊风。  
- Store 首屏：品牌「网桥 VPN」最大；一句说明；双 CTA；背景用抽象链路/网格纹理或真实机柜/终端氛围图做全宽平面，**禁止**首屏堆统计/卡片墙/浮动徽章。  
- 字体：Store 用有性格的无衬线展示+正文配对（勿默认 Inter/Roboto 堆砌）；App 跟各平台系统字体以保证 VPN 工具可读性。  
- 动效：Store CTA/步骤轻微入场；App 状态点呼吸/连接切换过渡（2～3 处即可）。

## 文案与空状态

### Store

| 位置 | 文案 |
|------|------|
| 品牌 | 网桥 VPN |
| Hero 一句 | 自建节点，自行掌控。无官方服务器，配置由你导入。 |
| CTA 主 | 下载客户端 |
| CTA 次 | 部署服务端 |
| 三步 1 | 在 store 下载并安装服务端（Debian / Ubuntu / CentOS / RHEL） |
| 三步 2 | 服务器执行安装后运行 `nbvpn show`，复制 URI 或扫终端二维码 |
| 三步 3 | 打开客户端添加服务器并连接 |
| 责任摘要 | 节点部署在您的服务器上。出口网络与合法使用责任由您自行承担。本产品不提供公共 VPN 节点。 |
| 密钥提示（服务端区旁） | `nbvpn show` 给出的 URI / 二维码 / 配置文件等同于密钥，请勿公开发布。 |

### 客户端

| 位置 | 文案 |
|------|------|
| 空态标题 | 还没有服务器 |
| 空态说明 | 从你的节点粘贴 URI、导入配置文件或扫描二维码添加。不会自动连接任何官方节点。 |
| 空态 CTA | 添加服务器 |
| 确认警告 | 连接信息包含访问密钥。仅从你信任的服务器获取。 |
| 删除确认 | 删除后需重新导入才能连接。确定删除「{name}」？ |
| Kill Switch 说明 | 开启后，VPN 断开时将尝试阻止流量泄漏（视系统能力）。 |

**空状态禁止**：推荐节点、试用线路、登录领取、热门服务器。

## 响应式 / 平台

| 平台 | 要点 |
|------|------|
| Store Desktop | 首屏一屏内完成：品牌+一句+双 CTA+三步可见或一滑即达；下载区两列变四列 |
| Store Mobile | 单列；双 CTA 叠放；命令块横滑可复制；锚点顶栏可收为菜单 |
| Windows / macOS | 窗口+托盘；添加流程用模态；文件导入为主，扫码为辅（摄像头或选图） |
| Android / iOS | 扫码为主入口之一；首次连接走 C-10 系统 VPN 授权；后台按系统 VPN 生命周期 |
| 四端一致性 | 同一套界面 ID 与文案键；布局跟平台规范，信息不增删 |

## 交接给前端的注意事项

1. **契约优先**：导入只认 `03-contract.md`（`.nbvpn.json` / `nbvpn:1?...` / QR=URI）；错误码映射 E_URI_* / E_PROFILE_*。  
2. **无账号墙**：Store 与 App 均不得加登录拦截下载或添加服务器。  
3. **无节点发现 UI**：任何「发现」「公共节点」「订阅」入口均视为缺陷。  
4. **本地名 ≠ profile.name**：C-06/C-08 只改 `localName`。  
5. **同时仅一条连接**：切换服务器必须先断后连，StatusBanner 反映真实状态。  
6. **Kill Switch**：设置页必有；默认策略跟 `01-spec` FR-C09；帮助文案跟平台能力诚实说明。  
7. **Store 数据**：版本与 SHA256 建议构建时注入静态 JSON，避免运行时依赖「节点 API」。  
8. **服务端区**：CentOS 卡片脚注 Rocky/Alma 可用同一系安装说明。  
9. **无障碍**：错误可复制；二维码失败提供「改用 URI/文件」出口。  
10. **实现后回写** `stack.md` 实际框架；本文不绑死 React/SwiftUI 等。
