# Brief — 项目业务摘要

> 路径约定：本文件位于项目根下 `docs/dev-workflow/context/`。
> 项目事实以本包为准；通用 skill 只提供流程。

## 一句话目标

向客户交付「网桥 VPN（NetBridge）」：完全去中心化的自建节点 VPN——用户用 `nbvpn` 在自有服务器安装与管理节点，并以配置文件 / `nbvpn:` URI / 二维码导入 Windows、macOS、Android、iOS 客户端；无默认官方服务器。

## 用户与角色

| 角色 | 是谁 | 要完成什么 |
|------|------|------------|
| 主用户 | 自建节点的个人/小团队 | 在自己的服务器上一键装 VPN，拿到连接信息，在客户端傻瓜式导入并连接 |
| 客户端用户 | 同一人的 Win / macOS / Android / iOS 设备使用者 | 粘贴 URI、导入配置文件或扫二维码添加服务器（可自定义名称）并稳定连接 |
| 下载站访客 | 尚未安装的用户 | 从落地页分别下载客户端与对应 OS 的服务端安装包 |
| 交付客户 | 采购本产品的客户方 | 获得可分发的全套安装包、落地页与可验收文档 |

## 核心场景

1. 用户打开下载站落地页 → 按需下载客户端（Win/macOS/Android/iOS）与服务端包（Linux 发行版或 Windows Server）。
2. 在自有 **Linux 或 Windows Server** 上用 `nbvpn` 一键/脚本安装 → 终端展示连接信息，并在无桌面环境下输出二维码。
3. 用户用 `nbvpn` CLI：快速使用、查看已安装配置、管理 VPN 服务（启停/状态/重启）。
4. 在四端客户端通过 **配置文件 / URI / 二维码** 任一种方式添加服务器，自定义本地名称后连接；默认无任何内置节点。

## 成功标准（可验证，≤3）

1. 新用户仅凭落地页 + `nbvpn` CLI，无需桌面 GUI，即可完成安装并拿到可扫二维码 / 可复制 URI / 可导出配置文件。
2. 同一节点信息可在 Windows / macOS / Android / iOS 客户端导入并稳定连接；断线可自动重连。
3. 产品无官方默认服务器、无强制账号；分发与文档明确「节点与出口责任在用户」；客户可按验收表完成全量交付验收。

## 高层约束（摘要）

- 时间/目标类型：**交付客户**；**不裁剪 MVP，全量同步开发**（四端客户端 + Linux/Windows Server 服务端 + 落地页并行推进，契约先冻结）
- 合规/安全：完全去中心化；协议 WireGuard；连接信息三形态全支持；安装包可校验
- 依赖系统：用户自备服务器与网络；不依赖我方中心节点
- CLI / URI：命令名与 scheme 前缀均为 `nbvpn`（易记）
