# Acceptance — S01 规格与连接信息契约

> 本刀验收以本文件为准；项目全局事实见 `docs/dev-workflow/context/`。

## 竖切目标

冻结可开发规格：WireGuard 自建模型、`nbvpn` CLI 命令面、连接信息三形态（配置文件 / `nbvpn:` URI / 二维码）等价契约，以及四端客户端与落地页的验收表——后续实现不得口头改契约。

## 范围内

- 产品规格与用户故事（服务端 CLI、四端客户端、落地页）
- 连接信息 schema（字段、版本、校验、三形态互转规则）
- `nbvpn` 子命令清单与傻瓜式输出约定（含终端二维码）
- 客户交付验收总表（映射到后续竖切）

## 范围外（本刀不做）

- 任何业务实现代码、安装包构建
- 视觉高保真（可引用设计任务，本刀只定信息与流程）

## 验收标准

| ID | 场景 | 前置 | 步骤 | 期望 | 优先级 |
|----|------|------|------|------|--------|
| AC-01 | 契约可读 | 规格已提交 | 打开规格中的连接信息章节 | 明确配置文件、`nbvpn:` URI、二维码三者载荷等价与版本字段 | must |
| AC-02 | CLI 面完整 | 同上 | 核对 `nbvpn` 子命令 | 覆盖：安装/快速使用、查看配置、展示三形态、服务启停/状态/重启 | must |
| AC-03 | 去中心化约束 | 同上 | 核对禁止项 | 无默认节点、无强制账号；与 `constraints.md` 一致 | must |
| AC-04 | 四端与落地页有验收映射 | 同上 | 查验收表 | Win/macOS/Android/iOS 与落地页均有可测条目 | must |
| AC-05 | 开放问题处理 | 读 open-questions | 查 Q-07/Q-08 | 已关闭或规格内写明默认假设并标风险 | must |
